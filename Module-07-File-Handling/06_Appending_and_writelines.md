
# 06 — Appending and `writelines()`

## 1. Introduction

File writing commonly involves two different requirements:

1. Replace the existing file contents.
2. Preserve existing contents and add new data.

Python provides:

- `w` mode for replacing/truncating existing contents.
- `a` mode for appending new data.
- `write()` for writing a string.
- `writelines()` for writing multiple strings.

---

# 2. Append Mode

Append mode is:

```python
"a"
```

Example:

```python
from pathlib import Path

path = Path("results.txt")

with path.open("a", encoding="utf-8") as file:
    file.write("TEST-106 PASS\n")
```

If the file already contains:

```text
TEST-101 PASS
TEST-102 FAIL
TEST-103 PASS
```

the result becomes:

```text
TEST-101 PASS
TEST-102 FAIL
TEST-103 PASS
TEST-106 PASS
```

Existing content is preserved.

---

# 3. Append Mode Creates a Missing File

If:

```text
results.txt
```

does not exist, opening it with:

```python
path.open("a", encoding="utf-8")
```

creates the file.

Therefore:

```text
a
├── existing file → preserve + append
└── missing file  → create + append
```

---

# 4. Append Mode Writes at the End

Append mode is intended for adding new data to the end of the file.

Example:

```python
with path.open("a", encoding="utf-8") as file:
    file.write("TEST-107 FAIL\n")
```

The new record is appended rather than replacing previous records.

---

# 5. Append Mode Does Not Add a Newline

This is an important rule.

Python does not automatically add:

```text
\n
```

when using append mode.

This:

```python
file.write("TEST-107 FAIL")
```

does not guarantee a new line.

For line-based records:

```python
file.write("TEST-107 FAIL\n")
```

is normally required.

---

# 6. Append Boundary Problem

Consider a file whose final line does not contain a newline:

```text
TEST-101 PASS
```

Then:

```python
with path.open("a", encoding="utf-8") as file:
    file.write("TEST-102 FAIL\n")
```

can result in:

```text
TEST-101 PASSTEST-102 FAIL
```

The records are concatenated.

Therefore, a robust append operation may need to consider whether the existing file already ends with a newline.

This matters when:

* Files are generated by different programs.
* Files are manually edited.
* Previous writes did not include newlines.
* Multiple tools contribute records to the same file.

---

# 7. `write()` vs `writelines()`

## `write()`

Writes one string:

```python
file.write("TEST-101 PASS\n")
```

## `writelines()`

Writes multiple strings from an iterable:

```python
file.writelines([
    "TEST-101 PASS\n",
    "TEST-102 FAIL\n",
    "TEST-103 PASS\n"
])
```

Comparison:

| Method         | Purpose                |
| -------------- | ---------------------- |
| `write()`      | Write one string       |
| `writelines()` | Write multiple strings |

Neither method automatically adds newline characters.

---

# 8. Appending Multiple Records

Suppose:

```python
results = [
    "TEST-104 FAIL\n",
    "TEST-105 PASS\n",
    "TEST-106 PASS\n"
]
```

You can append all of them:

```python
with path.open("a", encoding="utf-8") as file:
    file.writelines(results)
```

Existing content remains, and the new strings are written afterward.

---

# 9. `writelines()` Requires an Iterable of Strings

This is appropriate:

```python
results = [
    "TEST-101 PASS\n",
    "TEST-102 FAIL\n"
]

file.writelines(results)
```

Each element is a string.

The method writes the strings sequentially.

---

# 10. `writelines()` Does Not Insert Separators

This:

```python
results = [
    "TEST-101 PASS",
    "TEST-102 FAIL"
]

file.writelines(results)
```

can produce:

```text
TEST-101 PASSTEST-102 FAIL
```

because the strings contain no separator.

Correct:

```python
results = [
    "TEST-101 PASS\n",
    "TEST-102 FAIL\n"
]
```

---

# 11. Combining `write()` and `writelines()`

Both can be used with append mode.

Example:

```python
with path.open("a", encoding="utf-8") as file:
    file.write("TEST-101 PASS\n")

    file.writelines([
        "TEST-102 FAIL\n",
        "TEST-103 PASS\n"
    ])
```

The choice depends on whether the program has one string or multiple strings ready to write.

---

# 12. `w` vs `a`

This distinction is critical.

### Write mode

```python
with path.open("w", encoding="utf-8") as file:
    file.write("NEW RESULT\n")
```

Existing contents are truncated.

### Append mode

```python
with path.open("a", encoding="utf-8") as file:
    file.write("NEW RESULT\n")
```

Existing contents are preserved.

Mental model:

```text
w → replace
a → add
```

---

# 13. Practical Automation Example

Suppose an automation run starts with:

```text
TEST-101 PASS
TEST-102 PASS
```

During execution, additional results become available:

```python
new_results = [
    "TEST-103 FAIL\n",
    "TEST-104 PASS\n",
    "TEST-105 FAIL\n"
]
```

Appending them:

```python
from pathlib import Path

path = Path("results.txt")

with path.open("a", encoding="utf-8") as file:
    file.writelines(new_results)
```

produces:

```text
TEST-101 PASS
TEST-102 PASS
TEST-103 FAIL
TEST-104 PASS
TEST-105 FAIL
```

This is a common pattern when an automation system progressively records results.

---

# 14. Reusable Append Function

A simple reusable function:

```python
from pathlib import Path

def append_result(filename, result):
    path = Path(filename)

    with path.open("a", encoding="utf-8") as file:
        file.write(result + "\n")
```

Usage:

```python
append_result("results.txt", "TEST-106 PASS")
```

This keeps the file-handling logic in one place.

# 15. Common Mistakes

## Mistake 1 — Using `w` when you need to preserve data

Incorrect:

```python
with path.open("w", encoding="utf-8") as file:
    file.write("TEST-106 PASS\n")
```

If previous results are important, they will be lost.

Use:

```python
with path.open("a", encoding="utf-8") as file:
    file.write("TEST-106 PASS\n")
```

---

## Mistake 2 — Forgetting the newline

Incorrect:

```python
file.write("TEST-106 PASS")
```

when the next record should be on a separate line.

Correct:

```python
file.write("TEST-106 PASS\n")
```

---

## Mistake 3 — Assuming `writelines()` adds newlines

Incorrect assumption:

```python
file.writelines([
    "TEST-101 PASS",
    "TEST-102 FAIL"
])
```

The method does not add separators.

---

## Mistake 4 — Passing non-string values to text writing

`write()` and `writelines()` in text mode operate on strings.

Convert values when necessary:

```python
file.write(str(value))
```

or use formatting:

```python
file.write(f"{value}\n")
```

---

# 16. Key Takeaways

1. `a` mode preserves existing file contents.
2. Append mode writes new data at the end.
3. Append mode creates a missing file.
4. Append mode does not automatically add newlines.
5. `write()` writes one string.
6. `writelines()` writes multiple strings.
7. `writelines()` does not automatically add newlines.
8. Existing file boundaries should be considered when appending line-based data.
9. Use `w` when replacement is intentional.
10. Use `a` when existing data must be preserved.

---

# Interview Points

### What is the difference between `w` and `a`?

`w` truncates an existing file and writes new content. `a` preserves existing content and writes new data at the end.

### Does append mode create a file?

Yes, if the target file does not already exist.

### Does `writelines()` add newline characters?

No. The strings supplied to it must contain their required separators.

### What is a common problem when appending line-based data?

If the existing file does not end with a newline, the appended record can become concatenated with the previous record.

---

# Automation Principle

> Use append mode when results are accumulated over time, and explicitly control record boundaries such as newline characters.
